# scrctl 重构进展

scrctl 是独立产品，也是设备协议与恢复行为的验证项目。MaaFramework 后续倾向于
参考验证过的实现独立接入；本轮不引入公共 SDK、稳定 C ABI 或插件机制。

## 通用解析

- JSON 语法、序列化和值存储使用 nlohmann/json，旧 jsonlite 实现已删除。
- `src/json/Json` 只保留协议输入限制及非抛异常的取值辅助，不维护第二套值类型。
- 输入最多 4 MiB、嵌套最多 64 层；深度超限立即终止解析。
- JSON 整数向 int64 转换时检查溢出。配对 XPC 的 sequenceNumber 继续使用 uint64，
  其他整数字段超出 XPC int64 范围时报告错误。
- CLI11 处理短选项、别名、等号语法、参数个数、类型和帮助；项目只处理 crop、颜色、
  方向、verify 等领域规则。保留现有选项名称和有效值的含义。
- 非法数字、非有限/非正 scale、负尺寸/时间和带尾部垃圾的 crop / 颜色现在直接报错，
  不再像原实现一样静默转成零或接受部分字符串。参数错误退出码仍为 2。
- JSON 现在严格拒绝原解析器可能接受的非法数字、控制字符及孤立代理项。
  JSON 小数的文本表示由库决定，协议验证应比较值和 XPC 类型，不依赖小数拼写。

依赖优先用系统 CMake 包；缺失时 FetchContent 使用固定版本、SHA256 校验的上游归档。
不将上游源码复制进仓库。离线方式见 README。

## 第二轮：XML plist / Base64

- XML plist 的语法和转义交给 pugixml 1.16（MIT）。项目保留 plist 类型映射、
  单根结构校验、8 MiB 输入和 64 层值嵌套上限；不把非验证 XML 解析器当成完整 XML 校验器。
- binary plist 编解码保持原实现，共享 Value 移到 PlistValue.cpp。
- XML 输出的缩进和空元素拼写由库决定。数值尾部垃圾和非有限 real 现在直接拒绝。
- plist 和无线协议的 Base64 共用 OpenSSL EVP；保留 MIME 换行及省略尾部 padding 的支持，
  拒绝错误字符、长度和 padding。
- 真机短测：USB 截图 6 张、实时流 12 秒 222 帧；热点 Wi-Fi 截图 5 张、
  实时流 12 秒 222 帧。两条实时路径各完成两轮强制截图降级和恢复，正常退出。
- USB 手动 RemoteXPC 配对成功，新记录重新 pair-verify 通过，再使用该记录建立 Wi-Fi 会话。
  USB 免确认升级配对被设备拒绝；热点 RemotePairing 端口不接受直接 pair-setup。
- 本轮未验证长时间运行、物理断线、音频、输入、旋转和录制。强制切换测试也不等同于真实断网恢复。

## 第三轮：SDL 生命周期

- SdlRuntime 统一管理 SDL 初始化、部分初始化失败后的清理和 SIGINT / SIGTERM。
  初始化前保存调用者处理器，初始化后接管退出请求，SDL_Quit 后恢复原处理器。
- Application 通过声明顺序保证窗口、媒体源及声卡先析构，SDL 最后退出。
  输入测试、窗口创建失败等提前返回路径不再遗漏 SDL_Quit。
- 退出标志采用保证无锁的 atomic_flag；每次初始化清零，避免连续运行继承退出状态。
- 新增离线生命周期测试：信号转换和处理器恢复、重复初始化运行、视频初始化失败、
  无窗口回放退出后的 SDL 子系统清理。19 项离线测试通过。
- 真机使用热点 Wi-Fi 验证带音频流的 SIGINT、SIGTERM 和无效按键参数提前返回。
  音频出口使用 dummy 后端，验证开启与退出过程，不证明真实声卡输出或听感。
  本轮 USB 列表为空，未能重测 USB；上一轮 USB 短测不能代替本轮运行证明。

## 第六轮：系统 TCP 建连

- 创建 fd 后立即交给现有 Socket 管理，删除失败分支的手工 close。

- 超时针对每个候选地址的 connect 等待，不包含 DNS 解析，也不是整个握手的总期限。
- 本地回环测试覆盖重复失败时 fd 回收、主机名、阻塞和有期限连接、返回 fd 模式及数据传输。
  未专门注入 fcntl 失败或 poll EINTR。
- 构建和 20 项离线测试通过；热点 Wi-Fi 完成配对验证、隧道与目录建立，实时流 5 秒输出

## 第九轮：lwIP 生产接入（2026-10-07）

- 每个进程只有一个 lwIP 核心线程；netif、TCP / UDP、收包及定时器都在该线程执行。
- 每条隧道有独立 I/O 线程；核心回调只排队，出站队列上限 4 MiB。
- TcpStream 保留同步 ByteStream 接口，建连和发送上限 15 秒；应用取走接收字节后
  才归还 TCP 窗口。TCP 接收缓冲上限 4 MiB，UDP 队列最多 4096 包 / 16 MiB。
- 隧道关闭中断底层 I/O，通知等待中的建连、读、写，再回收线程与 netif。
  已发 FIN 的 PCB 用 ext-arg 销毁回调登记；移除 netif 前中止尚未释放的 PCB。
- 删除旧 TCP 序号、ACK、重传缺失的接收逻辑，以及手工 UDP 封包与分发。
  统计改为 lwIP 向应用交付的 TCP 字节，不再展示旧的乱序丢弃计数。
- 含探针的离线测试 22/22；生产适配层的 ASan 测试通过。
- USB 视频运行 35 秒，705 帧；Wi-Fi 运行 30 秒，406 帧并完成两轮截图切换。
  测试设备仍为 iPhone14,4 / iOS 27.0。
- 上述结果不证明物理拔插恢复、长期运行或多台真机并发。

## 第十四轮：关键帧无输出后的恢复

- 后备重建计时只参考成功解码的关键帧，不再由收到但解码失败的 AU 延后。
- PLI 重发每轮按时钟调度，避免仅收到 RTCP SR 时没有 AU 回调而停止请求。
- 软件解码不可用的一次性提示改用 std::call_once，避免多个媒体线程访问同一 bool。
- stall_probe 使用 CLI11 并复用设备连接选择，支持 Wi-Fi 与 --keep-pli；后者持续注入恢复关键帧失败并检查重建期限。

- 对外信息改为既有 mutex 保护的 payload type / 接收端口快照，重建开始撤销旧值，
  成功后发布新值，失败保持 0。停流及起流 RPC 不持锁，不扩大网络等待的临界区。
- 用实际生产 restart/getter、替换会话 I/O 的离线夹具验证首次成功、重建、失败及
  阻塞 RPC 期间的清零和非阻塞读取；1000 轮并发运行和原失败复现均通过 TSan。
- 真实截图 worker 的 20 轮失败、停止及回收检查中，退役容器每轮清空。
  这不覆盖远端 RPC 长时间阻塞，也不能替代物理断线和真机持续恢复验证。

## 第三十二轮：sanitizer 通道测试时限

- 03c2f41 的 sanitizer CI 仅 RemoteXPC 大缓冲测试触及 10 秒时限，其他 22 项通过，
  日志没有内存或未定义行为报告。用同样 Debug + ASan/UBSan 配置在本机直接运行，
  121 条判据全部通过，耗时 8.42 秒，确认原时限余量过小。

  有限时限检测卡死，不改变产品的网络超时或资源策略。

## 第三十三轮：TLS 握手失败的资源状态

- 证书与 PSK 握手使用局部 RAII 候选对象，仅在 SSL_connect 成功后发布通道句柄。
  无效 socket、错误 PEM、空 PSK、配置失败或对端拒绝后，valid 为 false，句柄为空；
  失败替换不会留下原通道或半成品，候选对象释放时不发送 TLS 关闭消息。
- 握手前清理当前线程的 OpenSSL 错误队列，并将 SSL_connect 的真实返回值传入
  SSL_get_error；检查协议版本配置及额外证书链的所有权转移。证书兼容策略、
  协议版本和进程级 SIGPIPE 行为保持原有约定。
- 新回归覆盖各阶段无效 PEM、无效句柄、空 PSK、旧错误队列、多次失败替换及
  失败后重新成功握手，并保留移动后的 PSK 回调测试。macOS 传输测试 53 条判据通过；
  完整 Release 与 Debug + ASan/UBSan 离线回归各 23/23。
- 最新代码 USB 20 秒输出 699 帧，模拟降级后恢复视频，视频序号缺口和音频解码失败

  Wi-Fi PSK 真机重协商或听感验证。Windows 原生失败路径回归另行记录。

## 第三十五轮：最小 ICMPv6 引用包诊断

- ICMPv6 诊断已扣除外层 8 字节头后，又多要求了 8 字节，导致完整的最小 UDP
  引用包没有显示端口。条件改为内层 IPv6 头 40 加 UDP 头 8 字节；转发路径不变。
- 通过生产 Stack 线程和内存隧道注入校验和正确的报文，验证最小完整引用、带载荷

## 第三十六轮：标准 FIR 构造与实验范围

- 旧公共 FIR 包为 24 字节，序号写入公共媒体 SSRC；按 RFC 5104 修正为单项 FCI
  的 20 字节布局、零公共媒体 SSRC、目标 SSRC 和 8 位请求序号。标准字节回归覆盖
  序号 0 / 7 / 255，旧实现 13 项失败，修复后 RTP 111 条判据全过，ASan 同样通过。
- `fir_probe` 复用同一构造器，保留的 fir205 明确标为非标准实验；PLI / FIR 的 RR
  配置与 rrsrc 统一，减少对照变量。产品恢复路径仍使用 PLI。
- 标准 FIR USB 单轮快测：29 次请求、26 个 IDR，首次计时请求后 32ms 收到 IDR，
  同时发送 RR 时跨过 20 秒租期，存活至 30 秒结束。随后两轮 none 均在约 20 秒到期，
  两轮 rrsrc 均存活到 30 秒，四轮各只有 1 个 IDR。
- 用户拔掉 USB 后，后续 PLI / FIR / FIR+fb 比较因连接中断未完成，不记录为反馈失败。
  撤回历史“FIR 有害”结论，保留旧非标准包的原始数据；配置差异、命令与剩余验证见
  [协议实验记录](coredevice.md#标准-fir-的修正与复测2026-10-07)。
- 最新完整 Release 与 Debug + ASan/UBSan 离线回归各 23/23；两探针均编译通过。

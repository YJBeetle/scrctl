# 与 scrcpy 的用法对照

常用操作以 [scrcpy v5.0](https://github.com/Genymobile/scrcpy/releases/tag/v5.0)
为参照，优先保持参数和快捷键的含义一致。新增功能按实际设备能力逐项验证。
本文记录当前实现；未实现的能力不会通过接受参数后忽略来模拟支持。

## 已对齐的操作

| 用途 | scrctl 参数或操作 |
| --- | --- |
| 镜像已连接设备 | 不带参数运行 |
| 选择设备 | `-s / --serial`，标识为 Apple 设备 UDID |
| 列出设备 | `--list-devices` 合并 USB 与 mDNS 发现；无线默认扫描 3 秒 |
| 禁止窗口控制 | `-n / --no-control` |
| 不采集音频，保持手机原有路由与播放状态 | `--no-audio` |
| 音频转到电脑、手机停止发声 | 默认行为 |
| 保留手机播放并转发音频到电脑 | `--audio-dup` |
| 关闭电脑音频播放 | `--no-audio-playback`；MP4/MKV 录制保留音轨，其余情况不采集 |
| 不采集视频 | `--no-video`；可继续播放音频，保留背景窗口的键盘控制 |
| 关闭电脑视频播放 | `--no-video-playback`；录制时仍接收视频，其余无视频消费者时不采集 |
| 关闭电脑音视频播放 | `-N / --no-playback`；保留录制和背景窗口控制 |
| 启动时全屏 | `-f / --fullscreen` |
| 运行中切换全屏 | `MOD+F` 或无修饰 `F11` |
| 退出窗口 | `MOD+Q` 或关闭按钮；终端可以按 Ctrl+C |
| 自定义快捷键修饰键 | `--shortcut-mod=lalt,lsuper`，默认左 Alt 或左 Super |
| 鼠标触摸 | 左键点击和拖动 |
| 物理键盘输入 | 普通按键保持完整按下集合，按各键抬起事件松开；使用设备键盘布局和输入法 |
| 粘贴电脑剪贴板 | MOD+V，显式写入手机剪贴板后发送 Command+V，支持 Unicode |
| 回到主屏 | MOD+H，或鼠标中键 |
| 调整音量 | MOD+↑ / ↓；转发主机重复 DOWN |
| 侧键 / 锁屏 | MOD+P |
| 恢复原尺寸 | MOD+G，按当前显示器比例换成窗口尺寸；不会为适应屏幕再次缩小 |
| 去掉画面留边 | MOD+W 或双击留边，保留窗口的一维并缩小另一维，保持画面中心 |
| 旋转电脑画面 | MOD+← 向左 90°，MOD+→ 向右 90°；不改变手机方向或录制 |
| 窗口设置 | `--window-title`、位置、尺寸、无边框、置顶、禁止屏保 |
| 自动窗口位置 | `--window-x=auto --window-y=auto`，也接受负数坐标 |
| 背景颜色语法 | RGB 或 RRGGBB，均可带 `#` 前缀 |
| 屏幕来源 | `--video-source=display`；旧 `stream` 值继续有效 |

`--shortcut-mod` 接受 `lctrl`、`rctrl`、`lalt`、`ralt`、`lsuper`、`rsuper` 的
逗号列表；任一选定修饰键按下时启用快捷键。Super 对应 Windows 键或 Mac Command。
普通 Q 和 Esc 不退出，默认不会截获右 Alt / AltGr+Q。按键重复不反复切换全屏。
电脑窗口快捷键在 `--no-control` 和文件播放模式中也可用；设备按钮在这些模式中
停用。设备转屏或可见画面尺寸变化时，
复用原来的窗口与渲染器，保留用户移动后的位置和调整后的显示尺度。
启动时的位置、尺寸与 `--scale` 不会再次应用；普通窗口按新画面比例适配尺寸。
全屏、最大化和最小化保持当前模式，回到普通窗口后再适配最终画面。

所选 MOD 自身和本地快捷键均不发给手机，即使先松开 MOD，也不会泄漏剩余
按键的抬起。普通键按下后再启用 MOD，仍会在原键抬起时释放它。默认 Mac 左
Command 是本地 MOD；要直接向手机发送 Command 组合可改用 `--shortcut-mod=lalt`。
窗口失焦、隐藏、最小化、转屏或退出时释放触摸、键盘和设备按钮。普通键盘的
主机重复 DOWN 不重发，设备侧长按重复和系统快捷键能否进入窗口仍需分别验证。

HOME、音量和侧键跟随真实 DOWN / UP；音量转发已经按住的主机重复事件，
HOME 和侧键抑制重复。先松开 MOD 或改变 Shift 后，仍松开最初选定的按钮。
键盘 HOME 与鼠标中键同时按住时，最后一个输入松开才释放 HOME。按住设备按钮
时不开始粘贴；本机旋转、镜像、缩放和全屏切换先松开设备输入，保留本地按键
归属到真实抬起，不由后续重复事件重新按下。发送失败后停止新输入，用原连接
尽力释放并保留首错。无视频背景窗口仍可控制按钮。
新的窗口按钮路径已通过离线 SDL 和 LiveSource 故障回归；Debian Wi-Fi 窗口已
确认 HOME、音量长按重复和锁屏，其他平台物理快捷键仍需真机验收。
当前中键固定为 HOME，未提供 scrcpy 的
可配置鼠标绑定，也没有 Shift+中键的另一套动作。

当前只转发物理按键，不把 SDL_TEXTINPUT 与按键同时注入。主机输入法提交的中文
尚未自动转到手机。MOD+V 可显式粘贴 UTF-8 文本，包含中文、emoji 和换行；
MOD+Shift+V 的旧式文字注入尚未提供。`--copy / --paste` 继续是独立剪贴板命令。

窗口粘贴先在独立连接写入，再另开连接读回逐字节核对；完成后由窗口线程
发送粘贴组合键。写入失败或读回不符不会粘贴。最多一个在途请求，文本上限
1 MiB，窗口循环在约五秒后取消；失焦、隐藏、最小化、画面几何改变、输入失败
和退出也取消旧作业。请求后发生新的有效触摸、设备键盘或按钮输入，也会取消
旧作业；即使已经完整抬起，也不会再向改变后的目标粘贴。MOD+V 自身不触发
这项取消。请求和完成时都要求没有设备按键或鼠标仍按住。
取消只关闭该作业的 Pasteboard 端点，不能撤销已接受的手机剪贴板写入。
--no-control、文件播放和无窗口模式不会读取电脑剪贴板或开始这项作业。
手机可能弹出“从 dtpasteboardd 粘贴”的确认；这是苹果远程剪贴板服务写入的
来源名称。允许后继续粘贴，拒绝则目标控件不会接受文字，scrctl 不绕过该权限。
Mac USB 已用手动 Command+V 验证 Safari 输入框收到中文和符号；普通 Q/W/E 也已
实际进入输入框。Debian Wi-Fi 窗口已确认普通 Q、输入与退格及中文/符号/emoji
粘贴；Windows Wi-Fi 窗口也已确认 Unicode 粘贴，测试时临时关闭 Parallels 共享
剪贴板，允许手机系统提示后完整文字进入 Safari 自有测试框，随后恢复共享模式。
共享剪贴板开启时曾出现远程 clipboard 读回冲突，不能用本轮结果代替该环境的验收。
多行、设备输入法及 Windows 普通键盘仍需分别验证。

G / W 只改变电脑窗口，不改变手机、采集或录制；全屏、最大化和最小化时不执行。
双击动作仅接受画面外的留边，两次点击都不发给手机。尺寸动作先松开设备输入，
取消尚未完成的窗口粘贴；仍按住的本地快捷键保留归属，直到真实抬起。
高 DPI 窗口尺寸只能取整数点，源像素除以显示比例后不足整点时取最近值，
例如 2× 显示器上的 1125 像素对应 563 点，不能保证每个奇数尺寸严格逐像素一致。
W 也容许整点取整产生的极小留边，避免反复执行时窗口持续缩小。

MOD+← / → 在当前显示方向上追加旋转，保留已有的显示翻转；下一帧或设备
转屏时仍保留用户的旋转偏移。已上传的静止画面立即重绘，不增加接收或录制
帧数。普通窗口按当前显示尺度适配；特殊模式下保持窗口状态，恢复后才适配。
旋转会松开设备输入并取消旧粘贴，本地按键仍保留归属直到抬起；普通方向键
继续发给手机。这两条快捷键在文件播放和 --no-control 下也可用，无视频播放
时不执行。

MOD+Shift+← / → 都水平镜像当前电脑画面；MOD+Shift+↑ / ↓ 都垂直镜像。
镜像按当前显示轴作用，先旋转再镜像与先镜像再旋转的结果可能不同。后续帧和
设备转屏保留用户的显示变换，静止画面立即重绘，鼠标落点使用同一变换还原。
镜像不改变窗口大小、采集、录制或手机方向；文件播放和 --no-control 下也可用。
它会松开旧设备输入、取消旧粘贴，并保留本地按键归属直到抬起。MOD+R 的设备
方向动作尚未提供。

`--no-control` 与 `--start-app`、`--test-touch`、`--test-button`、`--test-type` 相冲突时在连接设备前
报错。`--copy` / `--paste` 保留独立命令行为，使用时仍会显式执行剪贴板操作。

依据：[官方快捷键](https://github.com/Genymobile/scrcpy/blob/v5.0/doc/shortcuts.md)、
[官方窗口选项](https://github.com/Genymobile/scrcpy/blob/v5.0/doc/window.md)。

## 现有参数中的差异

| 项目 | 当前行为及使用边界 |
| --- | --- |
| `--record / -r` | `.mp4` / `.mkv` 保存所选轨道：默认 HEVC 和 AAC-ELD，`--no-audio` 只录视频，`--no-video` 只录音频；其他扩展名兼容裸 HEVC，建议 `.hevc`。MP4 最后视频帧显示 100 ms，参考 scrcpy 的收尾规则 |
| `--display-orientation` | 只改变本机显示，支持 scrcpy 的四个旋转角度与四个 flip 值；另保留 auto 扩展。flip 先水平翻转，再顺时针旋转，鼠标映射使用相反顺序 |
| `--orientation` / `--record-orientation` | 数字 `--orientation` 同时设置显示与容器录制方向；`--record-orientation` 只设置录制。按参数顺序覆盖；旧 `--orientation=auto` 仅设置显示 |
| `--crop` | 裁剪本机显示的源像素；视频和截图各使用自身的像素坐标，不改变设备采集或录制 |
| `--video-source` | 支持 display 和扩展值 screenshot（截图轮询）；没有 camera 能力 |
| `--no-window` | 不创建窗口并关闭视频播放；无录制或帧诊断消费者时不采集视频，可继续播放音频。录制时可跳过显示解码；按帧数退出、硬件解码、降级测试、截图及缺少 IDR 检查能力时保留旧解码路径 |
| 无视频的窗口 | 默认 256×256 点，显式宽高各自覆盖；不允许拖动调整尺寸。键盘、粘贴、全屏和退出沿用普通窗口，坐标触摸与 G/W 视频尺寸动作停用；目前没有应用图标 |
| 仅录音频 | `--no-video -r audio.mp4` 或 `audio.mkv` 保存一条原 AAC-ELD 音轨；不支持裸 AAC/ADTS。可用 `--no-audio-playback` 关闭电脑播放，音频路由仍由默认行为或 `--audio-dup` 决定 |
| `--copy / --paste` | 写入 / 读取设备剪贴板后退出，不模拟设备上的粘贴动作 |
| 窗口标题与比例 | 默认标题为 scrctl，默认背景为黑色；可以自由调整窗口比例 |
| Wi-Fi | `--list-devices` 用 mDNS 枚举；`--pair` 经 USB 创建/验证记录，`--wifi auto -s <UDID>` 自动选择无线候选；手动地址可用 `--wifi-port` 指定端口。scrctl 承担配对与连接，Android 的对应入口由 ADB 提供 |
| 编码控制 | 当前 Apple 服务决定尺寸、码率、FPS 和编码器，未提供相应覆盖参数 |
| 视频解码 | 默认软件解码；VideoToolbox 适配存在 NAL 长度限制，见 README |
| 音频路由 | 默认转到电脑，`--audio-dup` 保留手机播放，语义与 scrcpy 对齐；切路由可能暂时暂停手机播放器，需要手动继续。默认路由失败时音频禁用、视频继续，不自动改为双端播放 |

scrctl 已按 scrcpy 对齐显示与录制方向参数，录制旋转写入容器元数据，录制不支持
flip。显示仍保留 `auto` 扩展。scrcpy 的 crop 作用于采集，scrctl 的
`--crop` 只裁剪电脑显示。参见
[视频方向](https://github.com/Genymobile/scrcpy/blob/v5.0/doc/video.md#orientation)、
[录制](https://github.com/Genymobile/scrcpy/blob/v5.0/doc/recording.md)。

录制写入失败时停止写文件。解码模式的镜像继续，仅录制模式结束任务。
退出时检查文件刷新与关闭结果；
本次录制只要发生过文件错误，最终退出码就非零，文件可能不完整。

音频路由参照 [scrcpy 音频说明](https://github.com/Genymobile/scrcpy/blob/master/doc/audio.md#source)。
scrctl 的默认路由已在 macOS、iPhone14,4 / iOS 27 的 USB 与 Wi-Fi 音乐播放中验证：
电脑发声、手机无声，退出后手动继续可恢复手机播放。Debian ARM64 / PulseAudio
的 Wi-Fi 默认路由及 `--no-audio` 对照也已通过；Windows 与旧系统的该路由
尚未验收。程序不调整手机音量，也不自动按播放键。
本轮 QQ 音乐测试观察到默认路由激活时暂停一次，需要在手机上手动继续。

`--no-audio` 与 scrcpy 一致，跳过音频采集和路由请求，保持手机原有的播放与
输出状态；它不会自动恢复已经暂停的播放器。`--no-audio-playback` 关闭电脑
音频输出；没有 MP4/MKV 音轨录制时，也关闭采集和路由请求，效果与
`--no-audio` 相同。裸 HEVC 录制没有音轨，不会让音频继续采集。

录制 MP4/MKV 时，`--no-audio-playback` 保留音轨采集，仍使用默认电脑路由
（手机无声）。原始 AAC 直接进入录制器，跳过 PCM 解码、播放时钟补偿及播放缓冲；
来源、序号、时间戳与会话续期检查保留。要在录音轨时保留手机播放，可使用
`-r capture.mkv --audio-dup --no-audio-playback`，MP4 也支持同样组合。
`--audio-dup` 与显式或归一化后的 `--no-audio` 冲突，会在连接前报错。

本机播放后端初始化失败时不请求手机音频。起流后声卡打开失败时，MP4/MKV 录制
继续接收和保存音频；未录制时禁用音频，视频可继续，没有视频则退出。
设备答复无效（含路由不符）时停止音频收包及续期，并结束本次含音频的容器录制；
视频镜像可继续，纯音频或仅录制任务退出。
已切换的设备路由可能需等待音频会话到期
（当前租期 20 秒），播放器仍可能需手动继续；具体回收时刻未在所有设备上验证。
恢复时的无效协商答复不会进入反复切换路由的重试。
启动期间收到 Ctrl+C 时，程序在步骤之间检查退出请求，不再继续起流、切换
音频路由或执行设备输入。已经开始的连接和 RPC 仍可能等待各自的协议超时。

## 后续对齐顺序

1. 无线流程已接入主程序：继续验证正式配对、记录复用、按 UDID 自动选择及
   候选重试在更多设备和网络上的行为。Android 由 ADB 承担的配对与连接由 scrctl 处理。
   正式首次配对仍通过 USB；完全通过 Wi-Fi 首次配对尚未接入主程序。
2. Windows 音频：FFmpeg AAC-ELD 后端已接入，真实音乐解码及短时 USB 发声通过；
   无线播放已正常运行 120 秒。Mac 的重采样时钟补偿改善了刺啦声，新调节层
   仍需 Windows 回归；继续验证持续连接和安装包。
3. 容器录制：MP4 / MKV 和静态录制方向已接入 libavformat，继续验收音视频同步、
   跨平台和长期运行；录制旋转使用容器方向信息，显示 flip 已实现，设备采集裁剪仍待后续处理。
4. 键盘已接入窗口按下 / 抬起与释放边界；继续验证手机实际输入和主机系统键拦截。
   显式 Unicode 粘贴已接入，Mac USB 中文和符号通过，Debian Wi-Fi 的中文、符号
   和 emoji 通过；多行和 Windows 继续验收，主机 IME 文字模式单独设计。
5. 窗口动作：MOD+G / W、双击留边和原地转屏已接入，保留位置与用户显示尺度。
   显示旋转已接入 MOD+← / →，镜像已接入 MOD+Shift+方向键；继续验证原生
   窗口、真实键盘及真机转屏。
6. HOME、音量、锁定已接入主窗口 DOWN / UP 与共享释放；继续验证设备效果。
   Android BACK、APP_SWITCH、通知栏等不能直接套在 iOS 上。
7. 输出控制：采集、解码与播放已分离，音频单独播放、录制及无视频键盘窗口已接入；
   继续验证更多设备、平台和实际背景窗口输入。

这些是能力待办。离线 SDL 事件与键盘状态测试不能替代 VM、真实键盘、系统快捷键
拦截或设备目标控件中的输入验证。
